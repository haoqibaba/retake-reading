# Retake Reading · AI 邪修重建孩子阅读习惯

把一份视频字幕，做成一份带拼音、可以打印的读物。
**读完这一篇，才准看这一集。**

---

## 这套方法叫什么

| | |
|---|---|
| **方法** | **AI 邪修** —— 不跟孩子的逆反正面硬碰，绕到他最爱的地方，从侧面切进去 |
| **概念** | **读视频** —— 视频本来是看的，偏让他读；把视频读成一篇字 |
| **目标** | **Retake Reading / 重建阅读习惯** —— 把阅读装回他的日常 |

「邪」不是坏，是**偏门**：用偏门的路子，办正经的事。

### 为什么是「重建」，不是「培养」

「培养」是从无到有，是学校的语汇，默认孩子肚子里什么都没有。

「重建」承认另一件事：这个习惯本来有，只是后来塌了。小学低年级的孩子大多能捧着书看半天，是后来被读题、被要求、被比较，一点点磨没的。

所以我们不是从零教他读书，而是在把它重新盖起来。这个区别很重要——它不指责孩子懒，也不指责家长没做好，只说明一个事实：塌了，那就重新盖。

英文名用 **Retake** 也是这个意思：`retake` 在英语里是「重修、补考」，默认这门课上过、没通过、现在再来一遍。

---

## 这个 Skill 只做一半的事

**它不管怎么拿到字幕，只负责把字做成书。**

```text
【找字幕】  ← 这一段交给视频讲解，人工点几下就好
     ↓
  SRT / TXT 文件
     ↓
【做成书】  ← 这个 Skill 管这一段
     ↓
  带拼音的 Word
```

为什么不把找字幕也做进来：那一步要靠平台登录态、cookie、第三方工具，任何一环变化都会让整个流程坏掉。而人工操作只是「复制链接 → 粘贴到字幕网站 → 下载」，几秒钟的事，看一遍视频就会了。

**所以当用户只给了一个视频链接、没有字幕文件时：**

> 告诉用户：请先拿到字幕文件再回来。可以这样操作：
> 1. 复制视频链接
> 2. 粘贴到任意「字幕提取」网站（浏览器搜「B站 字幕 提取」，选个能用的）
> 3. 下载 SRT 文件
> 4. 或者用剪映这类工具生成字幕后导出
>
> 拿到文件发我，我接着做。

**如果视频本身没有字幕**，只能先生成一份：用剪映导入视频 → 自动识别字幕 → 导出字幕文件。这一步也由用户做。

**不要自己去抓字幕，也不要因为拿不到就凭标题编一篇文章。**

---

## 输入

**一个字幕文件**，三种都行：

| 格式 | 来源 | 怎么处理 |
|---|---|---|
| `.srt` | B 站字幕网站、大部分字幕工具 | 去掉序号和时间轴 |
| `.vtt` | YouTube | 去掉文件头、时间轴、样式标签 |
| `.txt` | 已经整理好的纯文本 | 直接用 |

**一期一个文件。** 不要一次塞多期，出错不好查。

---

## 第 1 步：清洗成纯文本

```bash
python3 scripts/clean_subtitle.py 字幕.srt
```

脚本会自动判断格式（看有没有 `-->` 时间轴），输出 `字幕.txt`。
它按「序号行 / 时间轴行 / 正文行」的位置解析，**不会把正文里的「747」「1969」当成序号删掉**。

输出会告诉你识别成什么格式、多少段、多少汉字。**汉字数要和视频时长对得上**——13 分钟的口播大约三千多字，如果你看到只有几百字，说明字幕不完整，先停下来问用户。

---

## 第 2 步：整理成文章

### 铁律：内容一律保留

**不做删减，不做压缩。**

原稿里的故事、数字、原理、例子、甚至说话人的口气，都是内容。你觉得啰嗦的地方，孩子可能正好爱看。

只做**形式层面**的整理：

- **分段**：把字幕的一行一句，合成自然段。一段只讲一件事
- **加小节**：给文章搭骨架，标题制造悬念（「它本来是一架货机」「为什么还在用钢索？」）
- **补标点**：字幕往往缺标点，按语气补上
- **修错别字**：明显的手误、同音错字
- **统一专名**：同一架飞机、同一个人，全文一个写法
- **术语加一句白话**：专业词第一次出现时，用一句话解释（FAA → 美国联邦航空管理局）

### 唯一可以动内容的情况

**开头那些完全没有画面感、孩子读不懂的梗**。比如「柯南里是波音 747」「显卡圈的核弹 GTX690」「背木兰辞接的还是波音 747」——这类内容对理解全文没有帮助，删掉孩子反而读得顺。

但**删之前要告诉用户删了什么、为什么删**，让用户决定。

### 不许做的事

- ❌ 不许编造：数字、时间、情节必须来自原文
- ❌ 不许「精简成摘要」：这不是写读书笔记
- ❌ 不许自己加评论、加升华、加结论

---

## 第 3 步：写成 JSON

三种块：

```json
{
  "blocks": [
    {"kind": "title", "text": "主标题"},
    {"kind": "title", "text": "——副标题"},
    {"kind": "h2",    "text": "小节标题"},
    {"kind": "p",     "text": "自然段……"}
  ]
}
```

- `title` 可以连续写两块，渲染成两行居中标题
- 标点、数字、英文不注音，脚本自动跳过
- 第一个块不能超过 255 字（Word 元数据限制，脚本会自动截断）

范例见 `assets/范例-article_source.json`（波音 747 那期的完整结构）。

---

## 第 4 步：生成 Word

```bash
python3 scripts/build_pinyin_docx.py 文章.json -o 孩子的读物.docx
```

首次运行需要：`python3 -m pip install pypinyin python-docx`

脚本会自动完成：

1. 逐字注音（内置 106 条多音字纠正，自动加载 `assets/多音字词表.json`）
2. 生成 Word 拼音指南（ruby）
3. 字体替代映射（楷体 → 汉仪楷体简 / STKaiti）
4. **文本完整性校验**（确认没有丢字）
5. **输出拼音疑问清单**

### 关于完整性校验

屏幕上会打印 `VERIFY_TEXT_COMPLETE: True`。

**它只检查汉字有没有丢，不检查拼音对不对。** 看到 True 不代表拼音全对，还要做第 5 步。

---

## 第 5 步：让用户确认拼音（必做）

脚本会在 docx 旁边生成一份 **`拼音疑问清单.txt`**。

它**不是把全文的多音字都列出来**——那样几十上百条，没人看得完。它只列**同一个字在文中出现了两种以上读音**的情况，因为那才是真正需要人判断的地方：

```text
1. 「长」—— 文中出现 2 种读音
     读 cháng（5 处）
        例：就是机身越来越【长】
     读 zhǎng（1 处）
        例：库克船【长】休息室

2. 「当」—— 文中出现 2 种读音
     读 dāng（11 处）
        例：【当】年如日中天
     读 dàng（3 处）
        例：维护不【当】
```

一篇三千字的文章，通常只出 3–6 组，**一分钟能看完**。

把这份清单直接发给用户，说：「这些字有两种读法，我按上下文各选了一个，你听一下哪句不对。」

**用户说读错时**，把「词语 + 正确读音」加进 `assets/多音字词表.json`，重新生成。词表命中的位置会被锁定，规则不会再覆盖它，所以**加了就一定生效**。

### 常见的坑（都实际踩过）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 「儿子」标成 `r zi` | 把「儿」都当儿化音 | 已在 v2.0 修复：后面接汉字就读 ér |
| 「第一次」标成 `dì yí cì` | 「一」变调没排除序数 | 已修复：序数、数字、年月、词尾读 yī |
| 「获得」标成 `huò de` | 「得」规则误伤 | 已修复：获取赢记懂晓等前面读 dé |
| 「之后的哥伦比亚」读成「的哥 dī」 | 词组误匹配 | **改文本比加词条干净**（换个说法） |

## 最终格式（用户确认过，别改）

| 项目 | 标准 |
|---|---|
| 汉字 | 楷体 |
| 拼音 | Times New Roman |
| 字号 | 正文 20 磅 / 拼音 8 磅；小标题 22/10；标题 24/11 |
| 拼音对齐 | 居中、**自然字距**（绝不用「分散对齐」，否则 `bù` 会被拉开、`cháng` 会被挤扁） |
| 行距 | **全篇单倍行距**（打印实测：多倍行距太散） |
| 页码 | 每页页脚居中自动编号 |
| 页面 | A4，正文左对齐 + 首行缩进 2 字 |

**必须用 WPS 或 Word 打开**：系统自带的快速预览不显示拼音层，不要以为拼音丢了。

## 交付前自检

- [ ] 清洗后的汉字数和视频时长对得上（13 分钟 ≈ 3000+ 字）
- [ ] 内容没被压缩，原稿的故事和数字都在
- [ ] 文本完整性校验 `VERIFY_TEXT_COMPLETE: True`
- [ ] 拼音疑问清单已给用户看过
- [ ] 单倍行距 + 每页页码都在
- [ ] **文章全文贴到对话框给用户看**（不要只丢文件路径）

## 规矩：别把这件事做成作业

读完就是读完。不用写读后感，不用回答问题，不用复述。

**规则只有一条：读完这一篇，才能解锁这一集视频。**

孩子认这套，是因为它在交换，不是在管教。

## 常见问题

**拼音被拉得很开 / 挤成一团？**
Word 拼音指南默认「分散对齐」会按汉字宽度拉伸。必须用 `rubyAlign="center"`（脚本已内置）。

**打开看不到拼音？**
用 WPS / Word 打开。Mac 快速预览（空格键）不显示拼音层，属正常。

**文件变大、拼音变成奇怪的域代码？**
WPS 另存后会把拼音转成 EQ 域，显示不受影响。想要干净原版，用脚本重新生成。

**楷体显示不出来？**
Mac 系统没装楷体。脚本已加「汉仪楷体简」（WPS 自带）和「STKaiti」（Mac 版 Word 自带）两套替代映射。

**字幕清洗后字数少了很多？**
可能字幕不完整，或者格式特殊。把原文件发回来看一眼。

## 系列用法

每一期是一条「读视频」：

```
读视频 · 第 01 期：阿罗哈航空 243 号班机（空难）
读视频 · 第 02 期：马航 MH370 失踪（悬案）
读视频 · 第 03 期：波音 747 的前世今生（机械）
```

孩子偏好哪类内容（空难、机械、动物、宇宙……），就顺着他的兴趣找。
